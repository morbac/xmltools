# XML Tools 插件 多语言汉化文档（简体中文）

## 一、项目信息

- **原项目**：https://github.com/morbac/xmltools
- **插件名称**：XML Tools（XML工具）
- **适用平台**：Notepad++
- **版本**：3.1.1.14 beta
- **汉化语言**：简体中文（zh-CN）
- **实现方式**：Win32 STRINGTABLE 多语言资源块（双语 DLL）
- **编译平台**：x64 Release，MSVC v143
- **PR 地址**：https://github.com/morbac/xmltools/pull/246

## 二、产出物与安装

### 2.1 产出物

| 文件 | 说明 |
|------|------|
| `x64/Release/XMLTools.dll` | 双语版插件 DLL（英文 + 简体中文） |

### 2.2 安装方法

1. 关闭 Notepad++
2. 将 DLL 复制到 Notepad++ 插件目录：
   - **x64**：`C:\Program Files\Notepad++\plugins\XMLTools\XMLTools.dll`
3. 启动 Notepad++，插件会**自动根据系统语言**选择显示语言

### 2.3 手动切换语言

在 Notepad++ 插件配置目录（`%appdata%\Notepad++\plugins\config\XMLTools.ini`）中设置：

```ini
[XML Tools]
language=auto     ; 自动跟随系统（默认）
; language=en     ; 强制英文
; language=zh-CN  ; 强制简体中文
```

也可以在插件的「Options（选项）」对话框中，通过「Language（语言）」选项切换。

## 三、多语言方案说明

### 3.1 核心思路

采用 **Windows 原生多语言资源块** 方案：

- 在 `.rc` 资源文件中放入**多套** `STRINGTABLE` 资源，每套对应一种语言（用 `LANGUAGE` 指令标识）
- 代码中通过 `FindResourceEx` 按当前语言 ID 查找对应的字符串资源
- 找不到时自动回退到默认资源（英文）
- 符合 Win32 插件本地化的标准做法，PR 容易被上游接受

### 3.2 为什么选这种方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **STRINGTABLE 多语言资源块（本方案）** | 标准 Win32 做法、单 DLL、自动选语言、加新语言不需改代码 | 字符串需提取到资源 |
| 直接替换式汉化 | 改动简单、速度快 | 只有中文，无法回退英文，不适合上游 PR |
| 运行时 ini 语言包 | 灵活、用户可自定义 | 需要额外文件，架构改动大 |

## 四、语言模块（Lang.h / Lang.cpp）

### 4.1 接口

```c
// 初始化（插件启动时调用，在 config.Read 之后）
void Lang_Init(HINSTANCE hInst, const wchar_t* langSetting);

// 加载字符串（返回 std::wstring）
std::wstring Lang_LoadStr(int id);

// 加载并格式化（printf 风格）
std::wstring Lang_LoadStrFmt(int id, ...);

// 便捷宏（返回 const wchar_t*，静态缓冲区，用完即走）
const wchar_t* Lang_Str(int id);

// 是否为中文环境
bool Lang_IsChinese();
```

### 4.2 字符串 ID 规划

字符串资源 ID 以 `30000` 为基址，分段使用：

| 范围 | 用途 | 数量 |
|------|------|------|
| 30000-30049 | 菜单项 | 29 |
| 30050-30099 | 消息提示 / 错误文本 | 41 |
| 30100-30149 | 通用 UI 字符串 / 语言选项 | ~30 |
| 30150-30199 | 选项属性名与描述 | ~30 |
| 30200-30209 | 选项组名称 | 7 |
| 30210-30225 | MSXML 功能名称 | 16 |
| 30230-30239 | 工具栏选项 | 2 |
| 30240-30249 | 代理选项 | 6 |
| 30250-30259 | XPath 对话框 | 5 |
| 30260-30269 | XSL 转换对话框 | 4 |
| 30270-30274 | libXML 错误 | 3 |

### 4.3 回退机制

当 `FindResourceEx` 找不到指定语言的字符串时：
1. 先尝试用户指定的语言
2. 找不到则通过 `LoadString` 加载默认资源（英文）
3. 再找不到则返回空字符串

保证了任何情况下至少有英文兜底，不会出现空白文本。

## 七、资源文件结构

RC 文件中新增两个语言资源块：

```rc
/////////////////////////////////////////////////////////////////////////////
// English (US) resources

#if !defined(AFX_RESOURCE_DLL) || defined(AFX_TARG_ENGLISH)
LANGUAGE LANG_ENGLISH, SUBLANG_ENGLISH_US
#pragma code_page(1252)

STRINGTABLE
BEGIN
    30000,  "Enable XML syntax auto-check"
    30001,  "Check XML syntax now"
    ...
END
...
#endif    // English (US) resources

/////////////////////////////////////////////////////////////////////////////
// Chinese (Simplified) resources

#if !defined(AFX_RESOURCE_DLL) || defined(AFX_TARG_CHINESE)
LANGUAGE LANG_CHINESE, SUBLANG_CHINESE_SIMPLIFIED
#pragma code_page(936)

STRINGTABLE
BEGIN
    30000,  "启用XML语法自动检查"
    30001,  "立即检查XML语法"
    ...
END
...
#endif    // Chinese (Simplified) resources
```

原有法语资源块保持不变，未做任何修改。

## 八、代码风格说明

### 8.1 使用 Lang_Str() 的典型场景

**菜单项：**
```cpp
// 原代码
menuitems.menuitemPrettyPrint = addMenuItem(L"Pretty print", ...);

// 汉化后
menuitems.menuitemPrettyPrint = addMenuItem(Lang_Str(IDS_MENU_PRETTY_PRINT), ...);
```

**带格式化参数的消息：**
```cpp
// 原代码
wchar_t msg[512];
swprintf(msg, 512, L"Line %d, pos %d: %s", line, col, text);

// 汉化后
std::wstring msg = Lang_LoadStrFmt(IDS_MSG_LINE_POS, line, col, text);
```

### 8.2 编码约定

| 文件类型 | 编码 | 原因 |
|---------|------|------|
| `.rc` 资源文件 | 原始 cp1252（法语块）+ 各语言块使用 `#pragma code_page` | Windows RC 编译器原生机制 |
| `.cpp` / `.h` 源文件 | UTF-8 with BOM 或 cp1252 / GBK（视原文件而定） | 保持原文件编码，减少 diff |
| 英文 STRINGTABLE 块 | cp1252 | 西欧代码页 |
| 中文 STRINGTABLE 块 | cp936 (GBK) | 简体中文代码页 |

> 💡 字符串在运行时以 Unicode（UTF-16）形式加载，不受源文件编码影响。

## 九、如何添加新语言

添加新语言（如日语、德语、西班牙语）**不需要改代码**，只需在 RC 文件中新增一套 STRINGTABLE：

1. 打开 `XMLTools.rc`
2. 复制整个 `Chinese (Simplified) resources` 块
3. 修改语言标识和代码页：
   ```
   LANGUAGE LANG_JAPANESE, SUBLANG_JAPANESE_DEFAULT
   #pragma code_page(932)
   ```
4. 翻译所有字符串
5. 在 Options 对话框的语言选项描述中补充新选项名（可选）
6. 重新编译

## 十一、设计取舍与已知限制

### 11.1 为什么对话框模板不做双语

对话框模板（DIALOGEX）如果做双语，需要在 RC 中复制一份完整的对话框定义（每个控件的坐标、大小、文本都要复制一遍），改动量大且维护成本高。

当前方案选择在 `OnInitDialog` 中通过 `SetWindowText` 动态设置文本，好处是：
- 只需维护一份对话框布局
- 翻译只涉及字符串，不涉及 UI 布局
- 改动小，PR 容易被接受

代价：
- 对话框标题在刚弹出时短暂显示英文（极短）
- 需要在代码中逐个设置控件文本

### 11.2 为什么不把所有消息都翻译

首批翻译覆盖了**用户可见的主要 UI 文本**（菜单、选项、对话框、核心消息）。

未翻译的主要是：
- 调试/日志输出（开发人员使用，英文更合适）
- 极少出现的边缘错误消息
- MSXML 长描述（每条几百字，翻译成本高，且懂 MSXML 配置的用户能看懂英文）

后续可以按需逐步补充。

## 十二、与纯汉化版的对比

| 维度 | 纯汉化版（v1） | 多语言版（当前 PR） |
|------|---------------|-------------------|
| DLL 语言数 | 只有中文 | 英文 + 中文，自动切换 |
| 修改文件数 | 16 个 | 21 个 |
| 改动规模 | 字符串替换 | 架构级改动 + 字符串替换 |
| 适合 PR | 不适合（破坏英文用户体验） | ✅ 适合（保留英文为默认） |
| 加新语言 | 需要新建一个分支 | ✅ 纯资源添加，不改代码 |
| 维护成本 | 每次上游更新都要重新汉化 | ✅ 只加新字符串 |
| DLL 大小 | ~3.1 MB | ~3.2 MB（多 100KB 左右） |
